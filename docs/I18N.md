# Translations (i18n)

SPAN speaks English (the default) and Danish. Every text a player reads comes from a dictionary through `BG.i18n`, numbers are formatted for the player's language, and switching the language in **Settings → Language** re-renders the open screens at once, without a reload.

This page explains how it works and how to add a string, a language, level text, plurals and formatted numbers.

## How it fits together

```
js/i18n/i18n.js             BG.i18n: lookup, plurals, events, DOM helper, formatting (no dependencies)
js/i18n/en/<area>.js        English dictionary, one file per area
js/i18n/da/<area>.js        Danish dictionary, same files, same keys
```

The areas are `core` (shared words), `hud` (title screen, level select, settings, in-level HUD), `editor`, `results`, `levels` (level names and hints), `famous`, `features` (goals, forces, daily, history, PWA, mobile) and `vehicles` (vehicle, train and material names). One file per area and language keeps the dictionaries apart, so several people can translate different areas at the same time without touching the same file.

`index.html` loads `i18n.js` and every dictionary **before anything else**, so any script may call `BG.i18n.t` while it loads. `tools/harness.js` loads the same files in Node (where the language is English unless a test sets it).

A dictionary file registers its texts with `BG.i18n.add(lang, area, entries)`:

```js
// js/i18n/en/hud.js
(function (root) {
  'use strict';
  root.BG.i18n.add('en', 'hud', {
    'hud.title.play': 'Play',
    'hud.title.continueLevel': 'Continue · {level}',
  });
})(typeof window !== 'undefined' ? window : globalThis);
```

Every key starts with its area (`hud.`, `core.`, `levels.` ...), so keys never collide between files.

## Which language

The language is decided once, when the page starts (`BG.Hud.init` calls `BG.i18n.init()`):

1. `?lang=da` in the URL (this page only, nothing is saved; handy for tests and screenshots);
2. the saved choice, `lang` in the settings (`BG.Storage.getSettings().lang`);
3. the browser: if `navigator.language` (the first preferred language) starts with `da`, Danish;
4. otherwise English.

`BG.i18n.setLanguage('da')` switches: it saves `lang` in the settings, sets `<html lang>` and the document title, re-translates every element marked with `data-i18n`, and fires `languagechange`.

## Adding a string

1. **Pick a key** in the right area: `<area>.<screen or part>.<name>`, for example `hud.levels.heading`.
2. **Add it to both languages**: the English text in `js/i18n/en/<area>.js`, the Danish one in `js/i18n/da/<area>.js`. `node tools/test-i18n.js --node-only` fails if a key exists in only one of them, or if the two use different `{params}`, plural forms or HTML tags.
3. **Use it.** There are two ways, depending on how the text gets on screen.

**Static markup** (built once, like the title screen): mark the element and let `BG.i18n.apply` fill it. `apply` runs again on every language change, so these elements never need extra code.

```js
const el = h(`<section>
  <h2 data-i18n="hud.levels.heading"></h2>                         <!-- text -->
  <button data-i18n-title="core.settings">${icon('gear')}</button>  <!-- title attribute -->
  <span data-i18n="hud.settings.volume">${icon('volume')}</span>    <!-- text after the icon -->
  <p data-i18n-html="hud.title.tagline"></p>                        <!-- trusted markup from the dictionary -->
</section>`);
BG.i18n.apply(el);
```

| Attribute | Fills |
|---|---|
| `data-i18n="key"` | the element's own text. Child elements (icons) stay; the text goes after them |
| `data-i18n-html="key"` | `innerHTML` (dictionary strings are trusted; use it for `<em>` / `<b>`) |
| `data-i18n-title`, `data-i18n-aria`, `data-i18n-tip`, `data-i18n-placeholder`, `data-i18n-alt` | `title`, `aria-label`, `data-tip`, `placeholder`, `alt` |
| `data-i18n-params='{"n":3}'` | params for any of the above |

**Text built in code** (a label that depends on state, a toast, a list rebuilt from data): call `t` and rebuild it when the language changes.

```js
function t(k, p) { return BG.i18n ? BG.i18n.t(k, p) : k; }

cont.querySelector('.lbl').textContent = t('hud.title.continueLevel', { level: shortLabel(target) });
this.toast(t('hud.settings.resetDone'), 'info');
```

Escape what you put into markup: `'<b>' + esc(t('core.comingSoon')) + '</b>'`.

## Re-rendering on a language change

```js
BG.i18n.on('languagechange', ({ lang, prev }) => { /* rebuild the text you built in code */ });
```

`BG.Hud` does this for the screens it owns (`Hud._onLanguage`): it refreshes the title screen, rebuilds the level select when it is showing, re-syncs the settings panel and forces the in-level HUD to redraw. Feature modules that **wrap** these methods (the Resume button, the Daily Challenge button, the badge chips) are re-rendered with them for free. A module with text of its own outside those methods subscribes itself; `pwa.js` and `mobile.js` are short examples.

The order on `setLanguage` is: save, `<html lang>`, `apply(document)` (every `data-i18n` element, including open modals), then the `languagechange` listeners.

## Data tables: chapters, campaigns, bonus chapters

Data such as the chapter list has text fields that other modules read (`ch.name`, `ch.desc`). Make those fields getters with `BG.i18n.lazy`, so every read returns the current language and nothing has to be rebuilt:

```js
const ch = BG.i18n.lazy({ n: 7, key: 'forces', from: 51, to: 53 },
  { name: 'hud.chapter.forces.name', desc: 'hud.chapter.forces.desc' });
ch.name;   // "Forces of Nature" / "Naturens kræfter"
```

`BG.Hud.registerCampaign(id, ui)` keeps getters, and also takes `nameKey`, `subKey` and `allLabelKey` for the tab name, the subtitle and the "all levels" button (`famous.js` registers its tab this way). `BG.Storage.CAMPAIGNS[id].name` reads `hud.camp.<id>.name`. The lock texts look for `hud.unlock.campaign.<id>`, `hud.unlock.gate.<id>` and `hud.unlock.rule.<id>` first and fall back to the generic keys, so a new campaign can word its own sentences.

## Level text

Level names and hints live in the `levels` area, keyed by level id:

```js
// js/i18n/da/levels.js
'levels.1.name': 'Vippebækken',
'levels.1.hint': 'Vejen skal gå fra bred til bred ...',
```

Read them with `BG.i18n.levelText(level, field)`: it returns the dictionary text in the current language, then the English dictionary text, then the field from the level data itself (`level.name`, `level.hint`). So the level JSON stays the English source of truth, and a level without dictionary entries still shows its own text. Generated levels (daily, endless) have no fixed id in the dictionary and show their data.

## Plurals

A plural entry is an object with one form per plural category. English and Danish both use `one` and `other`; `t` picks the form from `params.n` with `Intl.PluralRules` (or `n === 1` without Intl):

```js
'core.runs': { one: '{n} run', other: '{n} runs' },        // en
'core.runs': { one: '{n} forsøg', other: '{n} forsøg' },   // da
t('core.runs', { n: 3 })   // "3 runs"
```

Both languages must use the same shape (the test checks it). Do not build plurals with `n === 1 ? '' : 's'` in code.

## Numbers, money, lengths

| Helper | English | Danish |
|---|---|---|
| `num(1234.5)` (up to 2 decimals) / `num(2.5, 2)` (exactly 2) | `1,234.5` / `2.50` | `1.234,5` / `2,50` |
| `money(31975)` (the in-game currency is always `$`) | `$31,975` | `$31.975` |
| `meters(4.5)` (1 decimal; `meters(m, digits)`) | `4.5 m` | `4,5 m` |
| `percent(0.7)` (a ratio) | `70%` | `70 %` |
| `time(12.34)` / `time(125)` | `12.3 s` / `2:05` | `12,3 s` / `2:05` |
| `date(20261003)` (Date, timestamp or a YYYYMMDD day) | `3 Oct 2026` | `3. okt. 2026` |

They use `Intl.NumberFormat` / `Intl.DateTimeFormat` and fall back to a built-in formatter with the same output when `Intl` is missing. Units are joined with a no-break space, so `4,5 m` never wraps. `BG.Hud.money` goes through `BG.i18n.money`. Never format a number for display with `toFixed` or `toLocaleString('en-US')`; parameters are inserted as given, so format them first: `t('hud.x', { cost: BG.i18n.money(c) })`.

## Missing texts

A key missing in Danish shows the English text; a key missing everywhere shows the key itself. In development (`file://` and `localhost`) each missing key logs one `console.warn('[i18n] ...')`; the headless test fails on any such warning. On the live site nothing is logged.

## Adding a language

1. Add it to `LANGS` and `ORDER` at the top of `js/i18n/i18n.js`: its name in its own language (shown in the picker), the locale for numbers and dates, and the separators for the fallback formatter.
2. Copy `js/i18n/en/` to `js/i18n/<lang>/`, change the `add('en', ...)` calls, and translate.
3. Add the files to `index.html` and to the language list in `tools/harness.js`.
4. If the language has plural categories other than `one` / `other` (`few`, `many` ...), add them to the plural entries, and extend the plural check in `tools/test-i18n.js`.
5. If browsers in that language should start in it, extend `browserLang()` in `i18n.js`.
6. Run `node tools/test-i18n.js` and `node tools/gen-precache.js`.

## Tests

`tools/test-i18n.js` (see [TESTING.md](TESTING.md)):

1. **Dictionaries:** every key in both languages with the same `{params}`, plural shape and HTML tags; keys start with their area; every area file exists and is loaded by `index.html` and the harness; every literal key used in `js/` exists.
2. **Hard-coded string lint:** scans `js/ui`, `js/main.js`, `js/features` and `js/render` for English a player could read that does not go through `t()`: text and `title=` / `aria-label=` in markup, `textContent =`, `toast(...)`, `fillText(...)`, UI fields such as `name:` and `desc:`, and sentence-like strings. It prints a count per file (`--verbose` lists every hit with its line). False positives go into `tools/i18n-allowlist.json` (exact text or `/regex/`, globally or per file). Until every area is converted it runs with `--report-only` in `npm test`; the reference conversion (title screen, level select, settings, `BG.Storage` texts) must always be clean.
3. **Formatting** in both languages, with and without `Intl`, plus plurals, fallback, `lazy` and `levelText`.
4. **Headless Chrome:** switching the language updates the title screen, the open settings panel and the level select without a reload; the choice survives a reload; a Danish browser starts in Danish; the picker buttons are at least 44 px; no `[i18n]` warnings.

```sh
node tools/test-i18n.js                                # everything, strict
node tools/test-i18n.js --node-only --report-only      # what npm test runs
node tools/test-i18n.js --lint-only --report-only --verbose   # the list of strings left to extract
```
